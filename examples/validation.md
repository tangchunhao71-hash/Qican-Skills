# 验证记录 · Qican-Skills v0.5.0

## 深聊定性对照

用同一模型 GPT‑6.2‑Sol、低推理档，将四道源于实际交流的题目分别交给 v0.4.0 和 v0.5.0。两组使用相同题目与作答约束，分别提供该版赛博祈蚕入口和规则镜像。每组运行一次，没有外部检索或仓库操作。

| 观察项 | 结果 |
| --- | --- |
| 从一次经历提取交稿判断 | 新版只问了一次当时何时决定交接，给使用者留下了自由回忆的空间。旧版也会追问具体经历，同时给出了几个现成答案。两组都没有足够材料确认真实判断。 |
| 解释赛博祈蚕怎么思考 | 新版明确分开经验提取与共同研究，并用文章框架示例展示两种待核解释。旧版也会比较替代解释，而且更明确说明了什么观察能把两种解释区分开。 |
| 定位重复目录条目 | 在给定核查结果后，两组都只处理已确认的本机重复记录，保留账号插件。 |
| 无知识库入门 | 两组都允许从本轮口述开始、按需补资料。旧版给了一个可直接仿用的例子。 |

这轮只观察首次回复。真实知识是否提取准确、研究是否形成新认识、长文交接是否保全关键材料，以及使用者是否觉得交流自然，需要结合实际续聊和交稿检验。

# 验证记录 · 0.3.0

## 安装、构建与来源

在 Windows、Node.js 24.19.0、npm 11.17.0 运行 9 项测试。覆盖预览不写入、自定义目录、首次安装、多个宿主仅选一个、取消、同名保护、联合升级备份、过期文件清理、第二个 Skill 替换失败后恢复两个旧版、合成敏感样例、换行兼容和确定性构建。安装目录保留其他 Skill。也从 npm 实际打出的包执行一键安装，确认两个入口齐全。

在 Codex CLI 0.171.0 的隔离项目中，实际查询宿主的技能目录，两个 Skill 均被识别且启用。宿主也识别了仓库的插件目录清单。用独立 ZIP 解析器核对入口、文件内容及哈希，用 YAML 解析器读取两个 Skill 的头部和界面配置。Claude Code、Cursor、macOS、Linux 的实际安装与调用留待验证。

## 实际对话对照

用 GPT‑6.2‑Sol、低推理档，对同一个真实问题各运行一次。问题是没有作者的记忆和知识库的人如何使用插件，以及进阶方案是否值得做。给第一组相同的用户问题，给第二组增加公开单文件全文。两组都只回答问题。单文件组生成了完整答复，未调用文件或联网工具。

- 两组都给出直接使用、带自己的背景、接自己的知识库三层，样本未显示这三个建议由 Skill 独有。
- 单文件组进一步解释哪些事实会改变不同判断，用一个客户购买的例子区分上下文与方法，保留「没有关键缺口就继续」及「明确创作才使用文章规则」的边界。首版交付建议和这两条边界均可在正文定位。
- 这是一次定性对照。尚不能据此判断认知收益，也未验证情感、商业等各场景的实际长期效果。

另外用一个虚构的已确认提纲做文章阶段试跑。模型指出应补的两条证据并从现阶段交接。该次 Windows 受限会话拦截了模型发起的本地文件读取，所以这轮不能当作跨 Skill 共用镜像的实际读回。宿主发现和发行包相对引用已独立核对。
